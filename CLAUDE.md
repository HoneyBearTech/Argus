# Argus

Grafana dashboards as code for the homelab — version-controlled JSON dashboards, edited in VS Code and provisioned into Grafana automatically.

## Before Making Structural Changes
Read the project's notes first. They live outside this repo, in the owner's Obsidian vault **Chronos** at `~/Chronos/Projects/Argus/` (every file is prefixed `argus-`):
- `argus-roadmap.md` — phases, open questions, what's in scope now vs. later
- `argus-Dashboard-Catalog.md` — which dashboards to build, the question each answers, and the data source/exporter each needs
- `argus-Inventory.md` — what's running on the network (hosts, VLANs, services, existing monitoring pieces)
- `argus-Architecture.md` — pipeline, hosting, repo layout, authoring and deploy conventions
- `argus-Security-Considerations.md` — public-repo rules, exporter credentials, exposure checklist
- `argus-Decisions-Log.md` — ADR-style log of why decisions were made (entries marked **Proposed** still need the owner's call)
- `argus-Pass-Map.md` — pass-by-pass delivery log; add a row when a pass ships

Update these files as the project evolves — they're the source of truth for project direction. New decisions get a dated entry in `argus-Decisions-Log.md`; roadmap checkboxes get ticked as dashboards land.

**The notes never go into this repo.** Chronos is versioned in its own private repo; only commit or push it when the owner asks.

## This repo is public
- No IP addresses, internal hostnames, internal domains or service maps in anything committed — dashboards, provisioning, docs or commit messages. That detail lives only in `argus-Inventory.md`.
- No secrets. Credentials come from environment variables or files outside the repo; `.gitignore` covers `.env`, `secrets/`, `*.key`, `*.pem` — extend it rather than working around it.
- Review exported dashboard JSON before committing: Grafana bakes current variable values and cached query text into exports.

## Conventions
- Every dashboard has a stable, hand-chosen `uid` and `"id": null`.
- Reference datasources by pinned UID (see `provisioning/datasources/`), never by name or a hard-coded URL.
- Tag every dashboard `argus`; put the one-line "question it answers" from the Dashboard Catalog in its description.

## Layout
- `docker-compose.yml` — the server stack, running the **published images** `${ARGUS_REGISTRY}/argus-{grafana,prometheus,blackbox,loki}:${ARGUS_VERSION}`; per-install settings in a gitignored `.env` (template: `.env.example`). `images/<name>/Dockerfile` (build context = repo root) bakes the configs into upstream images: Grafana `13.2.4` gets `provisioning/` and `dashboards/` (at `/etc/argus/dashboards`, the provider's path) plus the home-dashboard env, keeps only the `prometheus`/`loki` bundled plugins and disables Grafana's plugin preinstaller (`GF_PLUGINS_PREINSTALL_DISABLED`, `GF_PATHS_PLUGINS` inside the image — runtime-downloaded plugins in the volume used to override the image's); Prometheus `v3.15.0`, blackbox `v0.29.0`, Loki `3.7.8` get their config files. Bump upstream versions in those Dockerfiles, `agent/Dockerfile`, `.github/workflows/ci.yml` and (for Grafana) the README's Grafana badge together.
- `docker-compose.source.yml` — override for running from a checkout (`COMPOSE_FILE=docker-compose.yml:docker-compose.source.yml` in `.env`): builds the images locally and bind-mounts dashboards, provisioning and configs so edits apply without a rebuild. **Production runs in this mode** (deploy = `git pull`); without it, compose would pull the published images instead.
- `docker-compose.proxy.yml` — override that adds Grafana to a same-host reverse proxy's Docker network (`ARGUS_PROXY_NETWORK`, external) with alias `argus-grafana`, so `GRAFANA_BIND` can be `127.0.0.1:3000`. Production uses it with NPM (proxy host forwards to `argus-grafana:3000`).
- `.github/workflows/release.yml` — on a `v*.*.*` tag, builds all five images (four server + agent) for amd64/arm64 and pushes them to GHCR and, when the `DOCKERHUB_USERNAME`/`DOCKERHUB_TOKEN` secrets exist, Docker Hub, with SBOM + provenance, signs each keylessly with cosign, then creates the GitHub Release from the tag's `## [x.y.z]` section of `CHANGELOG.md` (fails without one) with a source archive, `images.txt`, signed `SHA256SUMS` and build provenance. Tags: version, major.minor, latest. Release = changelog section, then a signed tag (`git tag -s`; public key in `.github/allowed_signers`). How users verify: `docs/verifying-releases.md`.
- `.github/workflows/ci.yml` is one job, **"Dashboards + config"** — the required check on `main`, so keep its name and add new checks as steps in it (it first logs in to Docker Hub when `DOCKERHUB_USERNAME` is set — `DOCKERHUB_PULL_TOKEN`, a read-only token, preferred over the release's `DOCKERHUB_TOKEN` — because anonymous pulls hit Docker Hub's shared rate limit): ruff, yamllint, actionlint, hadolint, `alloy fmt` diff, pytest + coverage (≥ 90 % of `scripts/`), check_dashboards, promtool config + PromQL tests, config checks, image builds, a Grafana boot test (counts provisioned dashboards/rules/datasources/contact points), compose config.
- Also in `.github/`: `codeql.yml` (Python + Actions), `scorecard.yml` (OpenSSF Scorecard, feeds the README badge), `scan.yml` (weekly Trivy scan of the five images → code scanning alerts), `dco.yml` (every PR commit needs `Signed-off-by` — commit with `-s`), `dependabot.yml` (upstream images, compose exporter images, Actions, pip — PRs merged by hand after a sandbox run, never auto-merged).
- `dashboards/<folder>/*.json` — provisioned with `foldersFromFilesStructure`, `allowUiUpdates: false`.
- `provisioning/datasources/argus.yaml` — the only place datasource uids are defined.
- `prometheus/prometheus.yml` — scrape jobs; each job reads `targets/<job>.json` (`file_sd`). `targets/` is gitignored; `targets.example/` holds placeholders that CI validates.
- `blackbox/blackbox.yml` — probe modules only; which URLs/servers get probed lives in `targets/blackbox_*.json` (labels `service`, `group`).
- `agent/` — the Argus agent: `Dockerfile` (FROM grafana/alloy + `config.alloy`), `compose.yml` (+ optional `plex` profile), `.env.example`. One container per monitored host, **pushing** host metrics (embedded node_exporter, `job="node"`), container metrics (embedded cAdvisor, `job="cadvisor"`) and container/NPM logs. Labels: `host` = `ARGUS_HOST`, `instance` = host name. GitLab Runner's CI job containers are filtered out of logs (by the runner's "managed" label, `__meta_docker_container_label_com_gitlab_gitlab_runner_managed`, before `loki.source.docker` — its `relabel_rules` don't stop a container being tailed) and container metrics (by their `runner-…-project-N-concurrent-N` and `runner-…-cache-…` names). The runner host's name is a forbidden pattern, so never write the label in its dotted form. Prometheus accepts pushes via `--web.enable-remote-write-receiver`; there are no `node`/`cadvisor` scrape jobs. A silent agent = series that existed in the last day but not now (`max by (host) (up{job="node"}) or max by (host) (max_over_time(up{job="node"}[1d])) * 0`). The published image is multi-arch; a locally built one must match the host's architecture (amd64 and arm64 both in use).
- `scripts/auto_deploy.py` + `deploy/systemd/` — optional auto-deploy for source mode: a user timer (every 5 min) fast-forwards to `origin/main` once the GitHub Actions "Dashboards + config" check passed, `up -d --build`, restarts services whose bind-mounted config changed, health-checks Grafana/Prometheus, rolls back and records the commit in `.git/argus-deploy-bad-commits` on failure; posts to `DISCORD_WEBHOOK_URL`. Docs: `docs/auto-deploy.md`.
- Prometheus auth: `secrets/prometheus-web.yml` (`--web.config.file`; example lists no users = no auth) and `secrets/prometheus_password` (user `argus`, always sent: Grafana datasource via `$__file{}` from a single-file mount with `create_host_path: false`, the `prometheus` self-scrape, auto-deploy's `/-/ready` check, agents via `ARGUS_PROMETHEUS_PASSWORD`). Every path needs the password once users are listed. CI boots Prometheus with `tests/fixtures/prometheus-auth/`.
- Exporter credentials are compose `secrets:` (files under `/run/secrets/`), never env: `<app>_api_key`, `qbittorrent_password`, `tautulli_api_key` (Varken's `VRKN_TAUTULLI_1_APIKEY_FILE`), `unifi_password` (unpoller `file://`), GitLab token inside `gitlab.yml`. Exceptions: pihole-exporter, the Plex exporter and tdarr-exporter (env only). Grafana's admin password and the Discord webhook are compose secrets too: `secrets/grafana_admin_password` (`GF_SECURITY_ADMIN_PASSWORD__FILE`; template empty, and the image's entrypoint `images/grafana/start.sh` refuses to start on an empty/unreadable file, since Grafana would fall back to admin/admin; only used when Grafana creates its database — rotate with `grafana cli admin reset-admin-password --password-from-stdin`) and `secrets/discord_webhook_url` (contact point `$__file{}`; template `https://discord.invalid/…`). Compose can't inject `environment:`/`content:` secrets into a `read_only` container, hence files. `auto_deploy.py` reads the webhook file, falling back to `.env`'s `DISCORD_WEBHOOK_URL`.
- Hardening (docs/security.md#hardening, enforced by `tests/test_configs.py`): every service in the three compose files has `cap_drop: [ALL]`, `no-new-privileges:true`, `read_only: true` (server: the `x-hardened` anchor); tmpfs `/tmp` only for Grafana (plugin sockets) and pve-exporter (Python). Root-default images (pihole-exporter, unpoller, snmp-exporter, qbittorrent-exporter, Plex exporter) run as `65534:65534`. So every file a container reads from `secrets/` must be 644 (no DAC_OVERRIDE). Only the agent adds a capability: `DAC_OVERRIDE` (its data dir is uid 473's; host files); it keeps host network (node_exporter's `/proc/net`) and host PID (PID 1's mounts; cAdvisor's per-container network) and the Docker socket, but is no longer `privileged` (costs only cAdvisor's unused `machine_*`, which needs `SYS_PTRACE`). A new `cap_add` must be from Docker's default set, commented, documented and listed in the test. Compose doesn't recreate a container when only an `env_file`'s contents change — use `--force-recreate`.
- `secrets/` (gitignored) — credentials: files Prometheus reads (`password_file` etc., mounted read-only) and env files for exporters (`pihole-exporter.env`, `unpoller.env`, loaded with `required: false` so the stack still starts without it); placeholders in `secrets.example/`.
- unpoller emits every UniFi device series once per UniFi device *tag*, so device queries must aggregate with `max by (name, ...)` or totals double-count. It refreshes every 30 s; UniFi panels set a 30 s minimum interval so `$__rate_interval` spans at least two updates.
- `snmp-exporter` is behind the `snmp` compose profile (`COMPOSE_PROFILES=snmp` in `.env`) because it needs `secrets/snmp-auth.yml`, which is mounted as a second `--config.file` next to the image's bundled `snmp.yml` (plus `snmp/synology-flashcache.yml`, Argus' hand-written module for SYNOLOGY-FLASHCACHE-MIB `.6574.103`, which the bundled `synology` module doesn't walk; CI dry-runs all three). DSM's `flashCacheReadHitRate` = ReadHits / (TotalRead − ReadSeqSkip): sequential reads skip the cache and don't count; TotalRead = ReadHits + DiskRead. The SNMPv3 user is SHA + AES (auth `synology_v3_sha` in production since 2026-10-15). SNMP targets (`targets/snmp.json`) carry `module` and `auth` labels that become the scrape's URL params. Synology reports disk IDs hex-encoded; dashboards decode `Disk N` with `label_replace`.
- Alerting is provisioned from `provisioning/alerting/` (rules, Discord contact point, policy). Grafana refuses to start if a provisioned rule is invalid — always load changes in the sandbox first. A rule's `__dashboardUid__` annotation is only accepted together with `__panelId__`. Provisioning files expand environment variables and `$__file{}` (that's how the Discord webhook gets in), so never name an env var like a template variable (`labels`, `values`).
- Home Assistant exports ~17k series; the `homeassistant` job keeps only the families in its `metric_relabel_configs` keep-list — add a family there before using it. HA exports Celsius; the Smart Home dashboard converts to Fahrenheit. Room/area names are personal, so queries select rooms by a generic rule (areas with a floor and exactly one sensor) and never name an area.
- Media exporters: one compose service per app (exportarr ×8 instances, qbittorrent-exporter), each behind a profile named after the app and reading the URL from `secrets/<profile>.env` and the API key from `secrets/<profile>_api_key` (compose secret mounted as `/run/secrets/api_key`; qBittorrent: `secrets/qbittorrent_password`); `targets/media.json` lists only enabled ones (with an `app` label) so missing apps never raise "target down". The `media` job drops `qbittorrent_torrent_*` (per-torrent, ~11k series). The Plex exporter image is amd64-only, so it runs beside Plex in `agent/compose.yml` (`plex` profile, `PLEX_SERVER`/`PLEX_TOKEN` in that host's agent `.env`); Prometheus scrapes it in its own 30 s `plex` job (`targets/plex.json`). A session is "live" while `rate(play_seconds_total[2m]) > 0`. On play metrics the exporter swaps labels: `title` is the show or movie, `child_title` the season, `grandchild_title` the episode, and the library name is in `library_type`. Test a Plex token from inside a container — Plex can exempt LAN clients from auth, which makes a bad token look good.
- Tdarr: `tdarr-exporter` (homeylab/tdarr-exporter, `tdarr` profile, distroless, uid 65532), job `tdarr` (30 s; `targets/tdarr.json` = `tdarr-exporter:9090`). Tdarr's URL in `secrets/tdarr.env`; the API key (only once Tdarr's login is on) goes there too, since the exporter reads it only from env — the third env-only exception. Per-library series carry only `library_id`; join `on (tdarr_instance, library_id) group_left (library_name) tdarr_library_info`. Queue/error counts (`tdarr_library_transcodes` / `_health_checks` by `status`) are gauges of Tdarr's current lists, so the errors alert compares with `offset 1h`; `*_completed_total` are counters. When Tdarr is unreachable the exporter still answers with only `tdarr_up 0`. Worker series (`tdarr_node_worker_*`, keyed by `worker_id`) exist only while a worker runs. Dashboard `dashboards/media/tdarr.json` (uid `argus-tdarr`); container panels use a `container` textbox (default `tdarr`).
- Tautulli: `varken` (HoneyBearTech/Varken 2.1.0, Prometheus-only from 2.0.0; `varken` profile, uid 1000, `${CONFIG_ROOT:?}/varken/config` bind-mounted at `/config` for the `varken.ini` it writes on first start — the homelab standard, never a named volume; the directory must belong to uid 1000; no tmpfs), job `varken` (30 s; `targets/varken.json` = `varken:9180`). Only its Tautulli module is on (every other `VRKN_GLOBAL_*_SERVER_IDS` is `false` in compose), GeoIP off (no MaxMind key), `LOG_TO_FILE=false`. Tautulli's address in `secrets/varken.env` (`VRKN_TAUTULLI_1_URL`, `_SSL`, `_VERIFY_SSL`), the API key in `secrets/tautulli_api_key` (compose secret, read via `VRKN_TAUTULLI_1_APIKEY_FILE`). Metrics (`server` label = Varken's config id, never a host): `varken_job_up` / `varken_job_last_success_timestamp_seconds` `{service, server, job}` (job `activity` = current streams every 30 s, `stats` = libraries hourly); `varken_tautulli_streams`, `_streams_by_decision{decision}`, `_bandwidth_bytes_per_second{network}`, `_sessions{state, media_type, transcode_decision, video_decision, quality, platform}`, `_library_items{library, type, item}`. A failed run drops that job's data metrics, so panels show "Not reporting", not stale numbers. Varken's `stream_details` is **on** (owner, 2026-10-15) for the Varken dashboard: `varken_tautulli_session_info{user, friendly_name, title, platform, quality, location, latitude, longitude, …}` and `_session_progress_ratio` per session — viewing data lives in Prometheus only, never in this repo, and the map stays empty while GeoIP is off. Dashboards `dashboards/media/tautulli.json` (uid `argus-tautulli`) and `dashboards/media/varken.json` (uid `argus-varken`: the original Varken dashboard ported to Prometheus, **generated** by Varken's `dashboard/make_dashboard.py --argus <this checkout>` — edit the generator there, not the JSON here; its Sonarr, Radarr, SickChill and Ombi panels stay empty while those modules are off); alerts `argus-tautulli-unreachable` (`varken_job_up` < 1 for 10 m) and `argus-tautulli-stale` (no good activity read for 10 m while up: a hung request — Varken's requests have no timeout yet).
- GPUs: `gpu-exporter` (utkuozdemir/nvidia_gpu_exporter, distroless uid 65534) in `agent/compose.yml`, `gpu` profile, NVIDIA runtime device reservation + `NVIDIA_DRIVER_CAPABILITIES=utility` (nvidia-smi comes from the host), port 9835. Prometheus job `gpu` (30 s, `targets/gpu.json` with a `host` label, like Plex) keeps only the families in its keep-list — add one there (and `test_gpu_job_keeps_every_metric_the_dashboard_and_alerts_use` checks it). Per-GPU series carry `uuid`; model/index from `nvidia_smi_gpu_info`. Locally, `--collect.backend demo` serves synthetic metrics. A missing driver: the container doesn't start (target down) or nvidia-smi fails (no `gpu_info` → "GPU not reporting").
- Proxmox VE: `pve-exporter` (prometheus-pve-exporter, `proxmox` profile) — a multi-target exporter: job `pve` scrapes `/pve?target=<node>&module=default&cluster=1&node=1` (a target labelled `cluster: "0"` skips the cluster-wide collectors, so in a cluster only one node reports guests). Token in `secrets/pve.yml` (compose secret, 644 — the image runs as uid 101; `PVEAuditor` role), CA in `secrets/pve-ca.pem` (`verify_ssl` is that path; the node's certificate must name the target address). Series carry only `id` (`node/<name>`, `qemu/<vmid>`, `lxc/<vmid>`, `storage/<node>/<name>`); names and nodes come from joining `pve_guest_info` / `pve_storage_info` `on (instance, id)`. VMIDs can repeat across unclustered nodes, so the Guests table joins on a `key` label (node/VMID). `pve_up` is 1/0 for nodes, guests and storage, and for `cluster/<name>` it's quorum; `pve_qdevice_up` exists only once a QDevice is configured (the panel then reads "None configured"); `pve_onboot_status` exists only when `onboot` is set. The deprecated non-counter traffic/IO gauges are dropped; use the `_total` counters. Job `pve_quorum` scrapes every node in `pve.json` with `cluster=1&node=0` and keeps only `pve_up{id="cluster/…"}` and `pve_qdevice_up` — each node's own view, for the quorum/QDevice alerts and stats (`min` = worst view), since `pve` reads the cluster from one node that may be the one that's down.
- GitLab CI: `gitlab-ci-pipelines-exporter` behind the `gitlab` profile; GitLab's URL and what to watch in `secrets/gitlab.yml` (644 — the image runs as uid 65534; the file holds an internal domain, so it can't be committed), the `read_api` token as `GCPE_GITLAB_TOKEN` in `secrets/gitlab.env`, the target in `targets/gitlab.json` (job `gitlab`). The exporter never forgets a label set: a ref whose trigger (`source`) or a job whose `failure_reason` changed keeps a stale series, so queries keep only the label set with the highest `gitlab_ci_pipeline_id` / `gitlab_ci_pipeline_job_id` (see `tests/promql/gitlab-ci.yml`). Runner metrics: job `gitlab_runner` (`listen_address = ":9252"` in the runner's config.toml). GitLab's health: job `gitlab_server` federates a `match[]` subset from GitLab's bundled Prometheus (`prometheus['listen_address'] = '0.0.0.0:9090'` in gitlab.rb — that reconfigure restarts Puma/Sidekiq); `exported_job` becomes `component` and the federated `up` is renamed `gitlab_component_up` so "Monitoring target down" (`up{job!="node"}`) doesn't fire for GitLab components. Sidekiq's per-queue `sidekiq_jobs_failed_total` resets and vanishes with Sidekiq; use gitlab-exporter's (`component="gitlab_exporter_sidekiq"`).
- Deploys (homelab-pull, the owner's pull-based deploy agent in the private homelab-ops repo; 0.4.0+): it rewrites `~/.local/state/homelab-pull/metrics/<stack>.prom` after every run and appends to `<stack>/deploys.log`. The agent mounts that state dir read-only (`HOMELAB_PULL_DIR` → `/var/lib/homelab-pull`, and its `metrics/` again as `/var/lib/homelab-pull-metrics`, so the fallback `./no-homelab-pull/metrics` is created by Docker — a missing textfile directory errors every scrape): node_exporter's textfile collector reads `/var/lib/homelab-pull-metrics` (series `homelab_pull_*{job="node", host, stack}`), Alloy tails `*/deploys.log` (`job="homelab-pull"`, labels `stack`, `result` = `ok`|`failed:<kind>`; from the start, lines > 6 days dropped). Metrics are written when a run ends and a run may take 45 min, so "silent" = no run for 50 min. Stack ids are the host names (internal) — never in committed examples. Dashboard `dashboards/ci/deploys.json` (uid `argus-deploys`); Loki deploy annotations on Host Health and Docker Containers.
- Logs: Loki runs either in the main stack (`loki` profile) or from `logs/compose.yml` on a host with more disk (production does the latter), port 3101, 30-day retention. The Argus agent (`agent/config.alloy`) ships Docker container logs (labels `host`, `container`, `compose_project`, `job="docker"`) and, where `NPM_LOG_DIR` is set, Nginx Proxy Manager access logs (`job="npm"`, labels `site`, `status`, `method`; Argus' own Blackbox probes dropped). Alloy drops lines older than an hour so first-start backfill doesn't hit Loki's age limit. Grafana's Loki datasource (uid `loki`) takes its URL from `LOKI_URL`. Loki bar gauges need `reduceOptions.values: true` — Grafana's Loki plugin returns instant metric results as one table.
- Tests: `tests/test_*.py` (pytest; `pythonpath = scripts`), `tests/promql/*.yml` — promtool test files whose `promql_expr_test` entries name the query (`rule: <uid>` = rule A with its threshold applied, `dashboard: <uid>` + `panel:` + `vars:`) instead of copying it; `scripts/promql_tests.py` resolves them. Test policy (CONTRIBUTING.md): new/changed rule or panel query → PromQL test; bug fix → regression test. Tool config in `pyproject.toml` / `.yamllint.yml`; dev tools hash-pinned in `requirements-dev.txt` (regenerate with `pip-compile --generate-hashes --strip-extras requirements-dev.in`).
- Project docs for the OpenSSF badges live in the repo: `GOVERNANCE.md`, `SUPPORT.md`, `CODE_OF_CONDUCT.md`, `CHANGELOG.md` (add to "Unreleased" with every user-visible change), `docs/` (quick start, architecture, interfaces, security, assurance case, dependencies, roadmap, upgrading, verifying releases). Keep them true when behaviour changes; badge answers are in the Chronos note `argus-OpenSSF-Best-Practices.md`.
- unpoller verifies the UniFi console's certificate unless `UNIFI_VERIFY_SSL=false` in `.env`. The blackbox image runs as uid 65534 (HTTP/DNS probes only; ICMP would need root).
- Grafana's home page is `dashboards/overview/homelab-overview.json` (`GF_DASHBOARDS_DEFAULT_HOME_DASHBOARD_PATH`, set in `images/grafana/Dockerfile`).

## Commands
```sh
python3 -m venv .venv && .venv/bin/pip install --require-hashes --no-deps -r requirements-dev.txt
.venv/bin/ruff check . && .venv/bin/ruff format --check . && .venv/bin/yamllint --strict .
.venv/bin/coverage run -m pytest && .venv/bin/coverage report
.venv/bin/python scripts/promql_tests.py --out /tmp/promql   # then: promtool test rules /tmp/promql/*.yml (see CONTRIBUTING.md)
python3 scripts/check_dashboards.py   # dashboard + public-repo checks (also run in CI); --fix reformats dashboard JSON
                                      # internal names it rejects: gitignored .forbidden-patterns locally,
                                      # ARGUS_FORBIDDEN_PATTERNS repo secret in CI — keep the two in sync
docker compose up -d                  # start / apply compose changes
docker compose restart prometheus     # after editing prometheus/prometheus.yml
```
Adding a scrape job: add it to `prometheus/prometheus.yml` with a `file_sd_configs` entry, add a placeholder in `targets.example/`, and put the real target in `targets/` on each host.
