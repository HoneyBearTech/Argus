# Argus

Grafana dashboards as code for the homelab — version-controlled JSON dashboards, edited in VS Code and provisioned into Grafana automatically.

## Before Making Structural Changes
Read the project's notes first. They live outside this repo, in the owner's Obsidian vault **Chronos** at `~/Chronos/Projects/Argus/` (every file is prefixed `argus-`):
- `argus-roadmap.md` — phases, open questions, what's in scope now vs. later
- `argus-Dashboard-Catalog.md` — which dashboards to build, the question each answers, and the data source/exporter each needs
- `argus-Inventory.md` — what's running on the network (hosts, VLANs, services, existing monitoring pieces)
- `argus-Architecture.md` — pipeline, hosting, repo layout, authoring and deploy conventions
- `argus-Security-Considerations.md` — public-repo rules, exporter credentials, exposure checklist
- `argus-Decisions-Log.md` — ADR-style log of why decisions were made (entries marked **Proposed** still need the owner's call)
- `argus-Pass-Map.md` — pass-by-pass delivery log; add a row when a pass ships

Update these files as the project evolves — they're the source of truth for project direction. New decisions get a dated entry in `argus-Decisions-Log.md`; roadmap checkboxes get ticked as dashboards land.

**The notes never go into this repo.** Chronos is versioned in its own private repo; only commit or push it when the owner asks.

## This repo is public
- No IP addresses, internal hostnames, internal domains or service maps in anything committed — dashboards, provisioning, docs or commit messages. That detail lives only in `argus-Inventory.md`.
- No secrets. Credentials come from environment variables or files outside the repo; `.gitignore` covers `.env`, `secrets/`, `*.key`, `*.pem` — extend it rather than working around it.
- Review exported dashboard JSON before committing: Grafana bakes current variable values and cached query text into exports.

## Conventions
- Every dashboard has a stable, hand-chosen `uid` and `"id": null`.
- Reference datasources by pinned UID (see `provisioning/datasources/`), never by name or a hard-coded URL.
- Tag every dashboard `argus`; put the one-line "question it answers" from the Dashboard Catalog in its description.

## Layout
- `docker-compose.yml` — the server stack, running the **published images** `${ARGUS_REGISTRY}/argus-{grafana,prometheus,blackbox,loki}:${ARGUS_VERSION}`; per-install settings in a gitignored `.env` (template: `.env.example`). `images/<name>/Dockerfile` (build context = repo root) bakes the configs into upstream images: Grafana `13.2.3` gets `provisioning/` and `dashboards/` (at `/etc/argus/dashboards`, the provider's path) plus the home-dashboard env, keeps only the `prometheus`/`loki` bundled plugins and disables Grafana's plugin preinstaller (`GF_PLUGINS_PREINSTALL_DISABLED`, `GF_PATHS_PLUGINS` inside the image — runtime-downloaded plugins in the volume used to override the image's); Prometheus `v3.15.0`, blackbox `v0.28.0`, Loki `3.7.8` get their config files. Bump upstream versions in those Dockerfiles, `agent/Dockerfile`, `.github/workflows/ci.yml` and (for Grafana) the README's Grafana badge together.
- `docker-compose.source.yml` — override for running from a checkout (`COMPOSE_FILE=docker-compose.yml:docker-compose.source.yml` in `.env`): builds the images locally and bind-mounts dashboards, provisioning and configs so edits apply without a rebuild. **Production runs in this mode** (deploy = `git pull`); without it, compose would pull the published images instead.
- `.github/workflows/release.yml` — on a `v*.*.*` tag, builds all five images (four server + agent) for amd64/arm64 and pushes them to GHCR and, when the `DOCKERHUB_USERNAME`/`DOCKERHUB_TOKEN` secrets exist, Docker Hub, with SBOM + provenance, signs each keylessly with cosign, then creates the GitHub Release from the tag's `## [x.y.z]` section of `CHANGELOG.md` (fails without one) with a source archive, `images.txt`, signed `SHA256SUMS` and build provenance. Tags: version, major.minor, latest. Release = changelog section, then a signed tag (`git tag -s`; public key in `.github/allowed_signers`). How users verify: `docs/verifying-releases.md`.
- `.github/workflows/ci.yml` is one job, **"Dashboards + config"** — the required check on `main`, so keep its name and add new checks as steps in it: ruff, yamllint, actionlint, hadolint, `alloy fmt` diff, pytest + coverage (≥ 90 % of `scripts/`), check_dashboards, promtool config + PromQL tests, config checks, image builds, a Grafana boot test (counts provisioned dashboards/rules/datasources/contact points), compose config.
- Also in `.github/`: `codeql.yml` (Python + Actions), `scorecard.yml` (OpenSSF Scorecard, feeds the README badge), `scan.yml` (weekly Trivy scan of the five images → code scanning alerts), `dco.yml` (every PR commit needs `Signed-off-by` — commit with `-s`), `dependabot.yml` (upstream images, compose exporter images, Actions, pip — PRs merged by hand after a sandbox run, never auto-merged).
- `dashboards/<folder>/*.json` — provisioned with `foldersFromFilesStructure`, `allowUiUpdates: false`.
- `provisioning/datasources/argus.yaml` — the only place datasource uids are defined.
- `prometheus/prometheus.yml` — scrape jobs; each job reads `targets/<job>.json` (`file_sd`). `targets/` is gitignored; `targets.example/` holds placeholders that CI validates.
- `blackbox/blackbox.yml` — probe modules only; which URLs/servers get probed lives in `targets/blackbox_*.json` (labels `service`, `group`).
- `agent/` — the Argus agent: `Dockerfile` (FROM grafana/alloy + `config.alloy`), `compose.yml` (+ optional `plex` profile), `.env.example`. One container per monitored host, **pushing** host metrics (embedded node_exporter, `job="node"`), container metrics (embedded cAdvisor, `job="cadvisor"`) and container/NPM logs. Labels: `host` = `ARGUS_HOST`, `instance` = host name. GitLab Runner's CI job containers are filtered out of logs (by the runner's "managed" label, `__meta_docker_container_label_com_gitlab_gitlab_runner_managed`, before `loki.source.docker` — its `relabel_rules` don't stop a container being tailed) and container metrics (by their `runner-…-project-N-concurrent-N` and `runner-…-cache-…` names). The runner host's name is a forbidden pattern, so never write the label in its dotted form. Prometheus accepts pushes via `--web.enable-remote-write-receiver`; there are no `node`/`cadvisor` scrape jobs. A silent agent = series that existed in the last day but not now (`max by (host) (up{job="node"}) or max by (host) (max_over_time(up{job="node"}[1d])) * 0`). The published image is multi-arch; a locally built one must match the host's architecture (amd64 and arm64 both in use).
- `scripts/auto_deploy.py` + `deploy/systemd/` — optional auto-deploy for source mode: a user timer (every 5 min) fast-forwards to `origin/main` once the GitHub Actions "Dashboards + config" check passed, `up -d --build`, restarts services whose bind-mounted config changed, health-checks Grafana/Prometheus, rolls back and records the commit in `.git/argus-deploy-bad-commits` on failure; posts to `DISCORD_WEBHOOK_URL`. Docs: `docs/auto-deploy.md`.
- `secrets/` (gitignored) — credentials: files Prometheus reads (`password_file` etc., mounted read-only) and env files for exporters (`pihole-exporter.env`, `unpoller.env`, loaded with `required: false` so the stack still starts without it); placeholders in `secrets.example/`.
- unpoller emits every UniFi device series once per UniFi device *tag*, so device queries must aggregate with `max by (name, ...)` or totals double-count. It refreshes every 30 s; UniFi panels set a 30 s minimum interval so `$__rate_interval` spans at least two updates.
- `snmp-exporter` is behind the `snmp` compose profile (`COMPOSE_PROFILES=snmp` in `.env`) because it needs `secrets/snmp-auth.yml`, which is mounted as a second `--config.file` next to the image's bundled `snmp.yml`. SNMP targets (`targets/snmp.json`) carry `module` and `auth` labels that become the scrape's URL params. Synology reports disk IDs hex-encoded; dashboards decode `Disk N` with `label_replace`.
- Alerting is provisioned from `provisioning/alerting/` (rules, Discord contact point, policy). Grafana refuses to start if a provisioned rule is invalid — always load changes in the sandbox first. A rule's `__dashboardUid__` annotation is only accepted together with `__panelId__`. Provisioning files expand environment variables (that's how `DISCORD_WEBHOOK_URL` gets in), so never name an env var like a template variable (`labels`, `values`).
- Home Assistant exports ~17k series; the `homeassistant` job keeps only the families in its `metric_relabel_configs` keep-list — add a family there before using it. HA exports Celsius; the Smart Home dashboard converts to Fahrenheit. Room/area names are personal, so queries select rooms by a generic rule (areas with a floor and exactly one sensor) and never name an area.
- Media exporters: one compose service per app (exportarr ×8 instances, qbittorrent-exporter), each behind a profile named after the app and reading `secrets/<profile>.env`; `targets/media.json` lists only enabled ones (with an `app` label) so missing apps never raise "target down". The `media` job drops `qbittorrent_torrent_*` (per-torrent, ~11k series). The Plex exporter image is amd64-only, so it runs beside Plex in `agent/compose.yml` (`plex` profile, `PLEX_SERVER`/`PLEX_TOKEN` in that host's agent `.env`); Prometheus scrapes it in its own 30 s `plex` job (`targets/plex.json`). A session is "live" while `rate(play_seconds_total[2m]) > 0`. On play metrics the exporter swaps labels: `title` is the show or movie, `child_title` the season, `grandchild_title` the episode, and the library name is in `library_type`. Test a Plex token from inside a container — Plex can exempt LAN clients from auth, which makes a bad token look good.
- GitLab CI: `gitlab-ci-pipelines-exporter` behind the `gitlab` profile; GitLab's URL and what to watch in `secrets/gitlab.yml` (644 — the image runs as uid 65534; the file holds an internal domain, so it can't be committed), the `read_api` token as `GCPE_GITLAB_TOKEN` in `secrets/gitlab.env`, the target in `targets/gitlab.json` (job `gitlab`). The exporter never forgets a label set: a ref whose trigger (`source`) or a job whose `failure_reason` changed keeps a stale series, so queries keep only the label set with the highest `gitlab_ci_pipeline_id` / `gitlab_ci_pipeline_job_id` (see `tests/promql/gitlab-ci.yml`). Runner and GitLab server metrics aren't collected yet (need sudo on those hosts).
- Logs: Loki runs either in the main stack (`loki` profile) or from `logs/compose.yml` on a host with more disk (production does the latter), port 3101, 30-day retention. The Argus agent (`agent/config.alloy`) ships Docker container logs (labels `host`, `container`, `compose_project`, `job="docker"`) and, where `NPM_LOG_DIR` is set, Nginx Proxy Manager access logs (`job="npm"`, labels `site`, `status`, `method`; Argus' own Blackbox probes dropped). Alloy drops lines older than an hour so first-start backfill doesn't hit Loki's age limit. Grafana's Loki datasource (uid `loki`) takes its URL from `LOKI_URL`. Loki bar gauges need `reduceOptions.values: true` — Grafana's Loki plugin returns instant metric results as one table.
- Tests: `tests/test_*.py` (pytest; `pythonpath = scripts`), `tests/promql/*.yml` — promtool test files whose `promql_expr_test` entries name the query (`rule: <uid>` = rule A with its threshold applied, `dashboard: <uid>` + `panel:` + `vars:`) instead of copying it; `scripts/promql_tests.py` resolves them. Test policy (CONTRIBUTING.md): new/changed rule or panel query → PromQL test; bug fix → regression test. Tool config in `pyproject.toml` / `.yamllint.yml`; dev tools hash-pinned in `requirements-dev.txt` (regenerate with `pip-compile --generate-hashes --strip-extras requirements-dev.in`).
- Project docs for the OpenSSF badges live in the repo: `GOVERNANCE.md`, `SUPPORT.md`, `CODE_OF_CONDUCT.md`, `CHANGELOG.md` (add to "Unreleased" with every user-visible change), `docs/` (quick start, architecture, interfaces, security, assurance case, dependencies, roadmap, upgrading, verifying releases). Keep them true when behaviour changes; badge answers are in the Chronos note `argus-OpenSSF-Best-Practices.md`.
- unpoller verifies the UniFi console's certificate unless `UNIFI_VERIFY_SSL=false` in `.env`. The blackbox image runs as uid 65534 (HTTP/DNS probes only; ICMP would need root).
- Grafana's home page is `dashboards/overview/homelab-overview.json` (`GF_DASHBOARDS_DEFAULT_HOME_DASHBOARD_PATH`, set in `images/grafana/Dockerfile`).

## Commands
```sh
python3 -m venv .venv && .venv/bin/pip install --require-hashes --no-deps -r requirements-dev.txt
.venv/bin/ruff check . && .venv/bin/ruff format --check . && .venv/bin/yamllint --strict .
.venv/bin/coverage run -m pytest && .venv/bin/coverage report
.venv/bin/python scripts/promql_tests.py --out /tmp/promql   # then: promtool test rules /tmp/promql/*.yml (see CONTRIBUTING.md)
python3 scripts/check_dashboards.py   # dashboard + public-repo checks (also run in CI); --fix reformats dashboard JSON
                                      # internal names it rejects: gitignored .forbidden-patterns locally,
                                      # ARGUS_FORBIDDEN_PATTERNS repo secret in CI — keep the two in sync
docker compose up -d                  # start / apply compose changes
docker compose restart prometheus     # after editing prometheus/prometheus.yml
```
Adding a scrape job: add it to `prometheus/prometheus.yml` with a `file_sd_configs` entry, add a placeholder in `targets.example/`, and put the real target in `targets/` on each host.
